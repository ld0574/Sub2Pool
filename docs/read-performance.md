# 页面读取性能

这轮优化只改变读取投影，不迁移数据库，不修改请求事实、价格、人工归因、合同或余额，也不启用真实限流。

## 首页、成员和账期汇总

`SummaryProjection` 在单次请求内复用轻量观测、已计价请求账本、采集覆盖和当前额度差额。账本使用 Decimal 前缀和查询时间窗口；需要更早历史时只读取新增区间，不重复计价已有请求。退出请求后立即丢弃，不跨用户或刷新缓存财务汇总。

当前额度差额只计算当前官方周期；历史核对接口仍逐周期返回历史证据。重置容差、切换 GPT-Load 后首个观测基线、人工调整和冻结规则不变。

首页返回 `Server-Timing: dashboard;dur=...`。本地计算超过 2 秒时输出 `Slow dashboard calculation` 日志；此耗时不包括网络传输和前端渲染。

## 请求记录和账号状态

GPT-Load 已保存的上游请求费用按纳美元整数在数据库聚合，最后转为 Decimal；缺失 usage 和未计价请求仍采用原有规则。CPA 继续使用当前配置逐条动态计价，只读取必要字段（包含 `usage_state`，避免逐条补查）。SQLite 整数求和溢出时回退到轻量流式计算，不改用浮点金额。

账号状态一次聚合本周期、近 30 天、今日的多个窗口，CPA 事件仅计价一次。账号状态的平均延迟仍包含零值，请求记录的平均延迟仍只包含正值。日期按 Django 当前时区解释，夏令时日界保持兼容。

账号状态仍实时查询上游。这里减少的是本地查询和计算，不保证上游慢响应、锁等待或后台历史重放导致的延迟同时消失。

## 统计图表

GPT-Load 按 Key 和日／小时在数据库聚合，CPA 与原始粒度使用轻量流式行。成员授权先作用于查询，再做聚合。桶的时间和 Key 提示来自真实请求，不用截断后的日／小时边界替代。小时范围跨夏令时转换时回退到流式分桶，避免合并两个重复的本地小时。

CPA/GPT-Load 容量图不再读取完整上游响应或粒子诊断 JSON，只保留端点折算所需字段；Sub2API 修正路径保持不变。

## 粒子轨迹

只缓存 `AdaptiveRangeOutput` 数值产物，不缓存页面响应、成员权限、姓名或账务记录。每次请求重新读取历史事实并构造完整模型输入；缓存键包含账号、算法版本、稳定种子、所有滤波配置、容量档位及模型全部字段（数组类型、形状、字节与基线标志）。历史证据、成本、合同权益、基线或配置变化都会改变对应输入并重新计算。

独立 `trajectory` 进程内缓存与登录节流分离，每个 worker 最多 4 份、每份不超过 8 MiB、有效期 10 分钟；较大产物不缓存。相同输入的并发计算合并，返回的数组隔离。缓存不可用或损坏时重新计算，重启自然清空。命中之后仍实时生成响应并过滤当前参与者权限。

## 回归和本地基准

在 `backend` 目录执行：

```bash
DJANGO_DEBUG=true .venv/bin/pytest monitor/tests
DJANGO_DEBUG=true .venv/bin/pytest -s monitor/tests/api/test_cpa_summary_performance.py monitor/tests/api/test_page_read_performance.py monitor/tests/api/test_trajectory_cache.py
```

测试覆盖 6 万请求、5000 观测的首页，10／1000／6 万请求的查询数量，混合计价、纳美元精度、溢出、缺失 usage、分页与授权、跨夏令时窗口，以及轨迹输入失效、并发复用、容量限制和权限更新。

本地合成数据上，6 万 GPT-Load 请求汇总固定 2 次 SQL；账号多窗口统计固定 2 次 SQL；小时图表固定 3 次 SQL。1000 点数值轨迹示例约 1.2 秒，完全相同输入的缓存命中约 1 毫秒（不包含读取事实和渲染响应）。这些是开发机结果，不是生产环境延迟承诺。
